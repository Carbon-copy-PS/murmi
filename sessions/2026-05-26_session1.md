# Session 1 — 2026-05-26

## What was built

Built the full Debate Sense prototype from scratch in a single session.

### Milestone 1: Live Transcription
- FastAPI backend with WebSocket-based session management
- React frontend with audio capture via Web Audio API
- Multi-device mic network — strongest signal auto-selected for transcription
- OpenAI Whisper integration for speech-to-text
- Real-time transcript broadcast to all participants

### Milestone 2: AI Sense-Making
- GPT-4o-mini analyzes transcript every 3 entries, extracts substantive agree/disagree claims
- Optional debate topic guides claim extraction
- Claims accumulate toward a threshold (5 per round)
- Progress bar on the recording screen
- Auto-switch to voting screen when threshold is reached
- Anonymous agree/disagree voting with live tallies
- Voting rounds cycle — earlier claims remain votable

### Infrastructure
- `start.sh` script that launches everything and prints phone-accessible URL
- Mock mode: fake debate transcript + mock claim extraction for testing without API keys
- Built frontend served directly from FastAPI (single port, works on mobile)
- Browser notification system (graceful fallback on iOS)

## Decisions made
- **Python + FastAPI** backend, **React + Vite** frontend
- **OpenAI Whisper** for transcription, **GPT-4o-mini** for claim extraction
- **Anonymous voting** — only totals shown, no attribution
- **Sector-specific debate topic** optional — AI infers if not provided
- **In-memory sessions** for now — no database yet

## Issues encountered
- iOS Safari: `Notification` API doesn't exist → white page crash. Fixed with `typeof` guard.
- Vite dev server doesn't work on mobile over network IP. Fixed by serving built frontend from FastAPI.
- OpenAI client crashes at import time without API key. Fixed with lazy initialization.
