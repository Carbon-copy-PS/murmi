# Session 2 - 2026-05-29

## What changed

Reworked Debate Sense's live transcription architecture after testing showed poor transcript quality, fabricated text, fragmented captions, and noticeable lag.

The app now uses a **single host recorder** model:

- The session creator becomes the host recorder.
- Only the host browser opens the microphone.
- Other participants join as listeners/voters and do not stream audio.
- The backend stores the host participant id and rejects recording controls or audio frames from non-host participants.
- If the host leaves, the backend can hand host ownership to another participant and stops any active recording.

## Problem this solves

The original prototype used a multi-device microphone network where every participant could stream audio and the backend selected the loudest active mic. In practice, that created several failure modes:

- Nearby laptops and phones captured the same room audio with different echo, delay, volume, and noise.
- The "loudest mic" could switch during one speaker's thought, breaking continuity.
- Short audio chunks gave the transcription model too little context.
- The realtime transcript sometimes produced confident but fabricated paragraphs.
- Multilingual speech across English, German/Swiss German, and French was especially unstable without enough continuous context.
- Vote statement extraction was downstream of the transcript, so poor transcript chunks could become poor voting statements.

The core product problem was not only transcription accuracy. It was trust. If users see fabricated transcript text, they cannot trust the statements generated for voting.

## New transcription flow

The new flow separates fast captions from final transcript truth:

1. The host browser captures mono audio with browser-level echo cancellation, noise suppression, and automatic gain control.
2. The frontend resamples audio to 24 kHz PCM and streams frames over the WebSocket.
3. The backend sends those frames to OpenAI realtime transcription for live partial captions.
4. The backend keeps a per-turn audio buffer for each completed speech item.
5. When the realtime service marks an item complete, the buffered audio is sent through a final transcription pass.
6. Only the final transcript text is merged into the transcript and used for argument/statement extraction.
7. Low-information fillers and known hallucination templates are rejected before display.

This means live captions may still be imperfect while someone is speaking, but the transcript entries and voting statements are based on the more reliable completed-turn pass.

## Related product changes

- Added participant language preference on join: auto, English, German/Swiss German, or French.
- Realtime prompts preserve the spoken language instead of translating.
- Same-speaker transcript chunks are merged for continuity.
- AI statement extraction now runs on completed speaker turns instead of only batch-analyzing every few transcript entries.
- The Vote tab shows all unvoted statements rather than hiding statements behind a single-card queue.

## Implementation notes

Backend:

- `Session.host_participant_id` tracks the host recorder.
- `SessionManager.is_host()` gates audio and recording controls.
- Non-host `audio_level`, `audio_frame`, `audio_chunk`, and `set_recording` messages are ignored.
- `RealtimeTranscriptionSession` buffers PCM audio per completed speech item.
- `TranscriptionService.transcribe_pcm16()` runs the final WAV transcription pass.
- `finalize_caption()` prefers the final pass when available and falls back to realtime text when needed.

Frontend:

- `SessionJoin` marks newly created sessions with `wantsHost: true`; joined sessions use `wantsHost: false`.
- `DebateRoom` sends the language and host intent during WebSocket join.
- Non-host clients do not call `getUserMedia()`.
- Host clients use one-channel audio with echo cancellation, noise suppression, and automatic gain control.
- Partial captions are cleared when final transcript entries arrive or when low-quality captions are rejected.

Environment:

- Added realtime transcription settings to `.env.example`.
- Added `OPENAI_FINAL_TRANSCRIPTION_MODEL` and `OPENAI_FINAL_TRANSCRIPTION_PROMPT` for the completed-turn pass.

## Tradeoff accepted

The change intentionally prioritizes transcript reliability over fully decentralized microphone capture.

Benefits:

- More continuous audio context.
- Fewer duplicate/echoing mic streams.
- Less hallucinated transcript text.
- More trustworthy statements for voting.
- Simpler mental model: one room microphone, many voters.

Costs:

- The host device placement matters more.
- A bad host microphone affects the whole session.
- Speaker diarization is still unresolved when using one shared room mic.
- The final transcript can appear slightly later than live captions because it waits for utterance completion.
